# 统一档案v5.3：本轮开发说明

本轮为统一档案v5.3，兼容现有本机档案与单次分析接口。日常运行沿用README启动方式和自己的`.env`配置。API密钥、私人数据库与本地备份不提交GitHub。

## 使用完整AI识别

按README配置`.env`并启动后端，打开`/profiles`，新建或选中人物，再点“添一段聊天”。核对双方和真实聊天日期，选择云端AI并同意发送脱敏资料。一般会先提取后核查，长聊天可能产生多次请求。具体相处方法和人物认识会自动更新；重大变化会简短询问。

## 免费回放示例

仅想看页面与更新规则时，在项目根目录的PowerShell执行：

```powershell
$env:JOKER_PROFILE_DIR = Join-Path $PWD 'data/preview'
$env:JOKER_CAMPUS_PREVIEW = '1'
$env:DEEPSEEK_API_KEY = ''
python scripts/seed_campus_preview.py $env:JOKER_PROFILE_DIR
cd backend
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

打开`http://127.0.0.1:8000/profiles?preview=1`。左侧“小夏”是两次短上传，“小禾”是三次信息丰富的连续上传。底部“开发预览”可从空白档案逐次加入`V5-R02`或`V5-L20`等案例，核对原话和变化。

示例人物与聊天均为虚构，回放已取得的模型结果并执行当前程序校验，不再调用API。部分输出经过最终程序离线重新校验，不代表模型每次都会得到同样结果。研究中使用的公开语料不放进产品示例；测试材料及录制输出不包含真实私人聊天。

这一模式使用独立`data/preview`目录，保留正式资料。要恢复完整AI，在新的终端按README正常启动；勿在正式多人服务启用开发回放开关。此版本尚未提供多人公网账号隔离。

## 主界面怎样精简

- 默认展示最多三条相处方法、四条简短人物认识，涵盖表达特点、兴趣理由和具体看法。方法兼顾边界、回应方式与可继续聊的内容。
- 其余认识、原文、适用范围、其他解释、修改按钮按需展开。近期事项、修改历史、资料维护合并或折叠。输入区通过“添一段聊天”打开。
- 新建档案表单折叠；左侧只显示人物和聊天段数。开发测试入口移到页面底部。五个使用方向没有成为五个入口。
- 未提炼出具体方法时不显示空的建议区。相处建议是可尝试方向，不意味着要迎合对方。

## 实际识别与保存流程

1. **提取依据。** 首轮看原始双人聊天，不带旧画像，不写建议，找具体要求、兴趣理由、观点、情境表现、明确态度、事项。允许零条，也允许一两条短聊天立即形成有用信息。
2. **处理长聊。** 保留消息ID和相邻发言，按约9000字的窗口读取，跨窗保留两条相邻发言。对明确表达的原话做关注提示，不把关键词当结论；长窗返回空且存在关注原话时，最多追加一次较短读取。
3. **核查含义。** 第二阶段对照完整原文检查“是否支持、是否需收窄、是否不支持、是否不确定”。纠正归属、类别和范围，再比较相关旧信息、提出更新及方法。不把首轮解释当证据。引用与类型校验仍由代码负责。
4. **有限推断。** 仅允许有范围的沟通特点假设，必须有依据、暂定理解、其他未排除解释和限制。不能由热情、单身、表情或回复速度认定爱情，不能推诊断或量化好感。
5. **保存和确认。** 普通新增与细化自动保存；有矛盾或重要态度、边界、特点反转时简短询问。争议项暂不进入建议，其余正常信息照常保存。引用真实但历史匹配错误时，保留新信息为独立条目，避免覆盖错误对象。
6. **后续使用。** 问钓翁按当前目的获取少量相关档案，保留日期、范围、有限理解和其他解释。过往明确态度可回看，不能当今天的真实感情。重复上传普通已处理材料不增加次数；人工修正受保护。

程序可以检查引用、发言者、时间、重复、结构和版本，不能证明所有语义理解正确。两次同模型调用也不是两个独立事实裁判。新格式出现Markdown围栏时仅去掉围栏；不猜补JSON内容或缺失原文。

若模型没有给具体方法，页面会从已保存的明确要求或具体兴趣、观点派生一个接话方向，展示实际内容；不会只写“聊游戏偏好”这种空话，也不会借此补造人格判断。人工修正后相关派生方法同样停用。

## 开发者需要知道的文件

| 位置 | 用途 |
|---|---|
| `backend/app/services/archive_extraction.py` | 两阶段提示、长聊窗口、关注原话、语义核查 |
| `backend/app/services/communication.py` | 引用校验、去重、时间、更新、确认、少量方法与检索 |
| `backend/app/services/campus.py` | 一个档案的简短派生视图 |
| `frontend/js/dossier.js` 与 `frontend/css/dossier.css` | 精简页面、原文展开、重要变化确认 |
| `scripts/check_archive_live.py` | 本轮200次/350万token账本与样本调用；自动测试已关闭 |
| `scripts/replay_archive_case.py` | 用真实录制输出执行离线重校验，不收费 |

默认使用兼容Chat Completions与JSON输出的服务。当前实际测试模型来自已配置服务：`deepseek-v4-pro`。模型/服务不同必须另行验证，不能依据本轮结果声称所有模型稳定可用。当前没有多人公网账号隔离。

## 借鉴资料

- [LongMemEval](https://arxiv.org/abs/2410.10813)：信息提取、跨会话、时间、更新与适时不知道分别验收。
- [Chain-of-Verification](https://arxiv.org/abs/2309.11495)：核查问题独立回到依据，而不靠草稿的说服性解释。原研究任务与人际聊天不同，本项目效果必须实测。
- [Lost in the Middle](https://arxiv.org/abs/2307.03172)：其测试模型会受长上下文信息位置影响，启发位置压力样本；不推断所有新模型表现相同。
- [Anthropic Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval)：保留对象与上下文，避免孤立切片。不直接照搬文档检索指标。

本轮具体错误、修正和剩余限制见 [验收报告](ARCHIVE_V5_EVALUATION.md)。
