# 档案 v7 本地预览说明

本版基于主分支 `0d886d6`，只重建档案核心，并保留队友已合并的导入、单次分析、小丑看板和社区功能。

## 打开方式

Windows 在项目根目录双击 `start-archive-preview.bat`，再打开 **http://127.0.0.1:8018/profiles**。

- 使用 `data/archive-preview/` 中的单独示例库，与原来的 `data/private/` 分开。
- 预置三组虚构示例用于检查页面和连续更新规则，页面会标明它们不是 AI 实测。
- 停止后，下次再双击即可。已有示例不会重复创建。
- 看原来联系人：使用正常的 `start.bat`，打开 **http://127.0.0.1:8000/profiles**。本版也修正了该启动器切换目录后找不到虚拟环境的问题。

虚拟环境已存在时，也可在项目根目录用 PowerShell 启动正常版本：

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

## 第一版能看什么

1. **双方画像**：默认TA，点击“我”切换。先看有情境的表达特点；展开依据可看来源并修正。不提供MBTI、依恋类型或好感百分比。
2. **重要信息**：具体兴趣与看法、明确边界与回应需要、承诺、待回应/待结果的事项、生日、目标与共同经历。分类在同一页，不是新增多个模块。
3. **连续更新**：具体事项保留提议/待定/答应/完成等状态；生日明确纠正可更新，无法解释的日期冲突需确认；旧聊天不按上传顺序覆盖新认识。
4. **更正传播**：画像记录来源签名，原依据修改、删除或待确认后，旧画像不再使用；打开页面本身不调用AI。

使用“上传聊天”继续原有导入、校对、双方核对和保存确认。需要完整语义提炼时开启AI；本地规则只能识别有限的明确表达，不是同等效果的离线模型。

## 先检查这几个地方

- “示例·两段短聊”：材料少时是否仍能找到具体兴趣、生日，以及双方有限的表达特点。
- “示例·持续了解小林”：兴趣有没有被压成“喜欢娱乐”；生日应是纠正后的11月19日、公历；复习资料应在过去事项中显示完成；咖啡仍未确定。
- “示例·待定不等于答应”：电影邀约没有变成双方约定；2月29日没有被擅自改成2月28日。
- 画像的依据能否展开；更正后旧结论是否消失；管理、上传是否容易找到。

预置示例只验证展示与规则，不能据此说模型识别准确。真实模型测试与剩余问题记录在本次交付报告中。

此次本机交付另保留“实测回放·短聊＋长聊（虚构）”：使用真实API返回的虚构案例响应，经修订后的流程重新回放；它与手写预置示例分别标注。回放不额外调用模型。

## 实现与兼容

- 继续使用现有 `Message` / `MemoryImport`、`communication_flow`、原文核查、加密存储、版本和提交机制。
- 扩展档案记忆类型与可选的 `item_state`，保持旧请求可用。`public_profile()`兼容增加`archive`，原`facts`、`method_cards`和`campus_board`仍保留。
- 新增`archive_v7.py`：重要信息视图、日期精度、双方画像综合与核查、来源变化失效。
- 画像只在AI导入产生相关变化后综合；通常新增两次请求。重复上传或单纯打开页面不重新综合；综合失败保留已保存的信息。
- 旧方法卡不占档案主界面，其接口暂留给旧消费者。没有删除问钓翁路由或修改队友的单次评分算法。
- 用户手工修正默认不发给AI；勾选允许后才可参与后续背景。模型图片注释不能独立证明性格、生日或关系态度。

## 本版限制

- 画像主要依赖已核查的交流特点和条件性表达偏好，尚未验证完整人格测量；模型核查仍可能漏错。
- 不支持农历自动换算、推送、自动祝福或完整日历；没有历法时保留未知，不推年龄。
- “待办/承诺”是相处背景记录，不自动发消息或替人安排。
- 旧资料只读展示或等待用户主动重新导入；不自动把历史私聊重发云端。
- 仍为本机预览版。社区账号与档案用户隔离不是本次完成项，不能直接把本版作为公众网站部署。

## 验证方法

后端新增`test_archive_v7.py`，覆盖双方归属、日期精度/纠正/冲突、乱序、闰日、事项状态、私有修正、画像失效和失败隔离。保留原模块回归测试。

前端新增`archive-v7.e2e.cjs`，检查真实服务返回的档案、人物切换、折叠内容、修正操作、导航保留、页面错误及窄屏溢出。运行结果以本轮交付报告为准。
