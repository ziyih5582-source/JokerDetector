# 档案 v8.3：开发说明与本轮验证

本轮围绕两个输出完善：**性格与相处画像**负责有限推断，**值得记住**负责具体信息。首页顺序为性格、重要信息、聊天建议；无建议时不显示空板块，历史与修改仍在管理中。

## 本地打开

在项目根目录双击 `start-archive-next-preview.bat`，浏览器打开 <http://127.0.0.1:8021/profiles>。若当前预览已启动，直接打开网页即可。

预览资料使用独立的 `data/archive-next-preview/`。其中两位原有联系人的已有缓存来自本地复制，本轮没有再次将其真实聊天发给模型；另有三组标明“实测示例”的虚构聊天结果。原有缓存不会自动变成新模型重新分析的结论。用户主动选择“上传聊天 → 只整理已有资料”并确认云端使用后，才会发起新的整理请求。

预览中新增的资料也保存在该预览目录。恢复资料需要同时保管 `profiles.sqlite3` 和 `profile.key`。这是本地开发预览，尚不具备公开网站所需的用户隔离。

## 具体改动

**1. 性格解读更完整，但首页不堆证据。**

每人最多四个特点，短标题下给两到三句解读，通常 60—100 字、最多 140 字。适用范围、其他解释和原话依据折叠。分析观察实际措辞、回应、幽默、分歧与修复，允许从语言作有限推断，不要求本人先自称某性格。作品观点、当时需要和具体事件分别保留，不直接人格化；材料不足可以为空。

**2. 先生成，再核查原始依据。**

继续使用现有消息导入与事实协议，档案综合独立消费这些消息。核查本人、原文、引用位置、概括层次和反例；最后做近义归组与文案检查。事实 ID 与互动片段 ID 混淆时，只有能精确回到同一人物原话的引用才允许修正。缺少或编造的原话不能靠改写文案补过关。

不要求填满固定人格维度，不生成 MBTI、心理诊断、确定动机或好感百分比。后台近义分组用于减少重复标签，并不是心理量表。

**3. 前后变化进入同一档案。**

同一人同一事项的新旧记录，需同时有模型核查、原始引文和可信时间先后。明确限定的新同意可更新旧的临时拒绝，旧内容进入历史；重大关系态度变化沿用已有简短确认。群体聚餐同意不能取消私人约会边界，相似名称的不同任务不合并。人工保护、禁用 AI 的条目不自动改写。

历史副本关联源记录；删除或纠正源记录会清理对应副本。保留旧认识时，新候选标为“本次未采用的记录”，避免误写成更早发生的事实。

**4. 保留不确定性与失败恢复。**

人工复核发现长案例把“好像是 12 月 15 号”写成确定生日。已补充核查提示和规则：日期推测不能丢掉限定词；阴阳历换算不能自行确定。修订后的连续案例保留已确认的农历生日，没有保留错误的确定公历日期。

另一个修复是任务范围不能被泛化的沟通偏好挤掉，例如“先改横轴、其余下次、今晚不用全部重做”。新结果把它记为实际负责者的任务，而不是对方的人格。

云端综合失败时，已获保存同意的脱敏互动片段可在有界、加密的本地依据库中等待重新整理；不接纳失败的模型结论，不自动重试付费。同版本完整重复上传不重复计费；识别提示与保护规则已有版本号，升级后可重新识别旧输入。

这里并非“不保存任何原文”：会保留核查用的脱敏原话片段。脱敏不能保证完全匿名；密钥和数据库同处本机也不等于具备公网账户隔离。

## 本轮测试记录

2026-10-19 独立新一轮测试，与前一轮分账。初始授权 200 万 token，用户随后追加 100 万；追加时沿用本轮账本，累计硬上限 **300 万**。

| 项目 | 记录 |
| --- | --- |
| 输入案例 | 159 组，145 个独立情境组，含 14 组配对或压力变体 |
| 设计上传 | 191 次；包括一两次短聊、连续上传、角色互换、姓名替换、引用与长文本 |
| 公开研究对话 | 16 组，独立标注来源，全部完成流程 |
| API 请求 | 856 次：852 次返回，4 次失败；包含 4 次虚构样本生成 |
| 服务商返回用量 | 2,813,003 token |
| 计入授权预算 | 2,873,835 token，含失败请求未知用量的 60,832 token 保守预留 |
| 追加授权后使用 | 894,599 token，仍在新增 100 万内 |
| 完整后端测试 | 465 项通过，0 失败、0 跳过 |

159 组的最终流程均已完成，其中两组长案例复用了事实与来源完全相同的已付费草稿，补做最终核查；没有把中断结果算作成功。单次最长输入为 **11,110 字符**的引用噪声压力案例；另有总计 **5,613 字符、分三次上传**的生成对话。很多气泡不一定等于很多文本，不能把其他千余字符案例宣传为超长自然聊天。

最终引用归属、精确原话、重复计费及重复标题等自动硬检查未报错。七条自动复核提示经人工查看，涉及三组适当不作性格推断、两条否定句被关键词误报，以及两条测试把自己的请求或责任误期望到对方名下。它们不是人格准确率。

本轮确实发现过自动检查遗漏的生日错误，因此不能由“自动检查通过”推出“所有分析都正确”。测试输入主要是构造案例与模型生成对话，生成与分析也使用同一服务商；没有真实人格金标准，不能声称对大学生人群的统计代表性或跨模型效果。

## 三个值得复看的结果

1. **新旧见面意愿**：旧记录“目前不愿单独见面”，后来明确“只同意这次校内公共咖啡厅、不去校外”。当前信息显示带限制的新安排，旧拒绝留在历史，没有扩成长期许可。
2. **短聊中的有主见**：对方被家人评价拿不定主意，但实际谈话说明自己按大纲选课、愿意听意见也保留取舍。新画像可给“温和有主见”，并折叠展示依据，不照抄家人的标签。
3. **连续三次聊天**：从合作、同好观点到关系澄清，综合形成“温和有主见、细腻共情、边界清晰”等有限理解，具体作品、兴趣参与和明确关系态度留在重要信息。此示例为虚构实测，不是对真实用户的性格判定。

## 仍需完善

- 部分标签仍偏泛或偏表达方式，主题偶尔拆得不够紧凑；相处建议也还需要人工核对是否值得现在提出。
- 已有错误缓存不会因升级静默删除；需要核对原话并修正，重新整理也不能保证消除所有历史错误。
- 本轮没有验证数万字自然中文聊天、截图 OCR 误差及多个模型组合下的整体效果。模型更换后应重跑固定案例，尤其检查空输出、引用归属和时间状态。
- 下一步更值得做的是少量经同意的真实使用盲评：特点是否贴切、信息是否重要、建议是否自然、哪里造成误解。不要以标签数量或用户认可度代替真实性。

## 研究借鉴及边界

核查流程借鉴了“生成后独立核对”的方向，但本实现没有完整复现 CoVe，也不能把该论文的实验效果当成本项目效果。[Chain-of-Verification，ACL 2024](https://aclanthology.org/2024.findings-acl.212/)

持续档案重点测试信息更新、时间先后与适当保留未知；这些也是长期记忆评测关注的能力。本项目使用自建情境，不能声称通过了原论文基准。[LongMemEval，ICLR 2025](https://proceedings.iclr.cc/paper_files/paper/2025/hash/d813d324dbf0598bbdc9c8e79740ed01-Abstract-Conference.html)
