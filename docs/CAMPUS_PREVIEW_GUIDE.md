# 校园档案 v4：直接预览与验收说明

本轮聚焦：有依据的人物认识 → 多次聊天修正 → 后续交流中调用。研究取舍见 [产品决策](CAMPUS_PRODUCT_DECISIONS.md)。当前为统一页面 v4.2，已移除五个场景入口；五个方向只影响需求与测试优先级。

## 打开

本机预览：http://127.0.0.1:8768/profiles?preview=1

已经在独立源码和独立虚构数据库上启动。无需下载或解压，原来的 D:\project\JokerDetector 未安装本轮改动。

若电脑重启或服务关闭，在PowerShell运行工作区 artifacts/start-campus-preview.ps1；它会返回预览链接，不改原项目。预览只绑定本机地址，暂非公网网站。

## 先检查这三个场景

1. 左侧选“小夏”：看慢热的情境、游戏玩法、公开边界、明确态度和一次书店邀约。点击原话核对；同意逛书店不能直接解释为恋爱。
2. 展开顶部“开发预览”，选“阿禾 · 关系变化”，点“从空白档案开始”，再逐段“加入这一段聊天”。应看到“先做朋友”到“愿意约会了解，但未在一起”，旧说法进入变化记录。
3. 选“小岚”检查剧透边界是否保留到看完；选“陈叔”看具体称呼与沟通方式；选“周老师”看12日改15日、先交初稿的要求。

还可选择台词、第三人转述、普通晚安等反例。前两者不应成为对方对你的感情态度，普通寒暄无需建一条人物认识。

这部分是**已保存的真实模型输出的离线回放**，经当前程序校验、写入和更新，不是重新调用模型。人物和聊天均为虚构。反例被拦截也会显示。初始两段来自早期提示版本，所以仍可看到旧输出的分类或冗余问题，没有人工改成漂亮的模型答案。

预览进程未加载原项目API密钥。上传任意新聊天时，有限本地规则只能识别少量明确表达；完整AI识别需在独立副本配置AI并按正常方式启动。不要把规则模式的留空当成完整AI识别结果。当前预览的样例回放不再收费。

## 已实现的档案能力

- 人物认识包含情境特点、兴趣与原因、具体观点、双方边界、支持需要、明确关系态度、实际互动、阶段与事件。
- 本人态度、用户自己的看法、一次互动分别标注；不提供好感百分比，不把单身解释成愿意与你交往。
- 每条能回看原文和范围；同主题追加依据，不同条件保留分支，明确变化保留旧版本。
- 已变更边界会停用过去的例外；补传旧聊天不会覆盖后来的态度或日期。
- 一句话修正后，原来的方法停用；用户看法不再冒充对方原话，默认不发给AI。
- 相处方法限制为少量具体内容，临时安排不扩展成通用建议。背景筛选可服务“怎么继续了解她”“聊什么”等问题，而不只依赖字面重复。
- 相处方法优先展示最多三条；人物认识与近期事项统一呈现，无内容的栏目隐藏。具体互动、修改历史、表单和旧分析默认折叠；无需切换场景。正文仅展示部分重点，其余可在全部记录查看。
- 跨年龄沟通依据这个人的原话与用户已给的关系标签，不按年龄生成刻板印象。

## 验证记录

真实调用：**21次，26,542 tokens，14组虚构关系案例**。上限100次，费用预算3万token；采用同一账本、请求前保守预留、无自动重试，未为凑次数继续调用。预算记录在工作区 artifacts/campus-v4-live.json。所有调用都有服务商usage返回。

识别阶段检查发现：

- 初期共同兴趣被拆成重复条目，修订提示限制重复、区分共同兴趣与误解澄清。
- “想解决报告”被推断成未经本人表达的心情，加入明确感受依据检查。
- 小说台词被截取成恋爱态度，改为同时检查完整发言，当前回放会拦截。
- 带“看完之后”条件的剧透边界不能按普通一天状态消失，改为保留条件。
- “支持需要”被模型归入“沟通要求/边界”的两次类别差异，经语义复核同样保留了原意；没有把类别差异当成错误或重试付费。

上一轮程序检查：后端186通过、9项可选环境跳过；朗读10通过；代码规范检查通过。浏览器检查了当时的场景筛选和原有交互。

统一页面本轮检查：档案相关后端51项通过，前端语法与本轮Python规范检查通过。浏览器已验证兴趣、特点和边界在同页呈现，连续两次关系更新、前后变化、背景检索、修正后的用户看法、文字注入防护、跨年龄资料和改期后的节点。已保存截图供回看。本轮新增付费API调用0次；上述21次为上一轮数据。

允许有限推断已获用户确认，但新的证据提取、独立核查、有限推断入库流程仍是下一阶段方案，见 [核心识别改造与逐步验收](ARCHIVE_EXTRACTION_NEXT.md)。当前预览主要验证统一展示和现有更新流程，不代表换模型后的准确性已验证。

这不是21次全部语义正确的准确率报告，也不是独立用户效果研究。原始输出的错误保留在录制资料中；最后的防护修订以离线回放验证，没有假称全部修订都再次接受了线上模型验收。

## 仍有边界

语义匹配仍依赖模型；同义主题可能漏合并或分类不理想，引用真实也不保证解释完全正确。当前用少量假想案例调试，未验证真实大学生群体的沟通改善效果。未实现多人公网账号与权限隔离。

相比上一版，本轮未修改 services/analyzer.py、services/unified.py 或 api/routes/analysis.py 的单次聊天算法。扩展的是档案识别提示、长期更新与展示、问钓翁的档案背景检索。为预览增加的案例接口仅在 JOKER_CAMPUS_PREVIEW=1 时开放。

源码目录是 work/profile-campus-v4/JokerDetector；暂未上传GitHub，也没有覆盖你的正式项目。正常部署不需要开启开发预览接口。
