# 联系人档案 · 实验版

本功能已与原「聊天分析」**合并为同一条流程**：只有一个页面、一次提交，同时产出情感分析与档案更新。原来的独立档案页（`/profiles`）并入同一个单页工作台（`/` 与 `/profiles` 返回同一份 `index.html`），旧链接仍可访问。

界面上的名字是**「交心 · 思源湖研究所」**（上海交通大学 · 把一段聊天投进湖里，量一量、记下来、说出口）。导航共七个去处：**首页**（思源湖画卷 + 三步上手，不放鱼）、**谈心分析**（贴入聊天、选档案、一次分析）、**找钓翁聊聊**（和 AI 聊感情问题，可读某个人的档案）、**人物档案**（按人累积的喜好与观察）、**心理学依据**（心理学理论整理，带出处）、**使用说明**（项目功能与算法说明）、**设置**（AI 配置、湖面动画与背景音乐）。另有一个不在导航里的结果页**「分析结果」**（仍保留「水纹」这个别称：五维墨线 + 档案变动）。板块之间没有方框，只用细墨线与朱砂区分。

## 启动

需要 Python 3.10 或更高版本，推荐 Python 3.12。在解压后的项目目录运行：

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r backend/requirements.txt
.venv\Scripts\python -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

macOS / Linux 把 `.venv\Scripts\python` 换成 `.venv/bin/python`。打开 http://127.0.0.1:8000/ 即可，首页就是思源湖画卷。也可以进 `backend/` 目录跑 `python -m app.main`（等价入口）；项目根的 `make run` 就是上面这条 uvicorn 命令。请使用一个服务进程，不要使用多 worker 或公开部署本实验版。

无需 API Key 即可体验完整的人物档案、喜好提取、追加更新与修正流程。云端 AI 已是项目统一配置：把 `.env.example` 复制为 `.env` 并填入 `DEEPSEEK_API_KEY`（也支持同名进程环境变量，优先级更高），启动时自动加载。进入「设置」页点「验证调用」：只有真实请求成功才标记为已验证，验证仅发送固定虚构示例，会产生少量 API 用量。之后回到「谈心分析」，核对脱敏预览并勾选云端选项即可。改动 `.env` 后在「设置」点「重新加载配置」即可生效，不必重启；未配置时后端的提示也会指向「设置」页。模型名称须与 API 地址对应的服务商一致，密钥只留在服务端、不会下发到浏览器，也不会写入档案。

## 三分钟演示（融合流程）

1. 进「谈心分析」，点「填入示例一」填进一段虚构片段，再点「辨认说话的人」。
2. 核对「我（自己）」和「对方」的对应关系，展开脱敏预览：示例电话号码应显示为 `[电话]`。
3. 在右栏「这段聊天记在谁名下」里输入「小林（演示）」→「新建档案」，它会被自动选中。
4. 勾选第一项确认，点「开始分析」。
5. 结果页（「分析结果 · 水纹」）同时给出两块内容：**水纹**（分数、判定、五维墨线、双方比对）和**人物档案变动**（新增「喜欢徒步、喜欢咖啡」，并列出依据）。
6. 回「谈心分析」，点「填入示例二」，再次提交：加入「不喜欢咖啡、喜欢看电影」，两条咖啡记录显示冲突；徒步不会新增重复依据。
7. 到「人物档案」里修正一条信息，再重复导入相同片段，确认不会重复更新或覆盖修正。
8. 可以导出 JSON 档案、删除某条信息，或删除整个联系人。

示例均为虚构内容。页面不会自动导入附件中的聊天数据。

## 原有 AI 情感分析长文（已并入同一次提交）

「谈心分析」页勾选「本次使用云端 AI」与「同时生成 AI 情感分析长文」后，同一次提交就会返回长文，结果页的「AI 情感分析长文」板块展示约 1000–2000 字内容；实际字数由模型输出决定。不勾选时只运行本地统计，不产生任何云端请求。

长文调用失败时会展示具体原因，并保留本地统计。长文生成有独立的 90 秒响应超时；连同档案提取／分类，整个分析可能等待约两分钟。云端请求先替换发言者昵称并进行基础脱敏；自动脱敏不能识别所有隐私。长文只展示在当前页面，不写入档案库；重复提交同一片段并勾选长文时，会重新生成长文，但不会重复导入档案。

## 找钓翁聊聊（情感对话）

入口在导航「找钓翁聊聊」（页面上的钓翁是「思源湖畔垂钓多年的老者」）。两种谈法：

- **不谈具体的人**：单纯倾诉。AI 不做诊断、不贴标签，先接住情绪再看问题，一次回复 300–500 字。
- **谈某段关系**：在「这次想聊谁」里选定一个档案条目，勾选「把 TA 的档案作为背景交给 AI」。AI 会先读到这个人的脱敏档案（日常喜好、沟通观察、冲突与人工修正标记），建议因此能落在具体的人身上。

这个功能需要云端 AI 可用（`.env` 里配好 Key，或已存在同名环境变量）；未配置时页面会直接提示，并把你引到「设置」。

边界与隐私：

- 只有勾选之后才发送档案片段；勾选后可以展开「查看将发送的档案内容」，看到的就是真正会发出去的背景文字（含"这是本机观察、可能有误"的说明），所见即所发。
- 你说的话在发送前会在本机做基础脱敏（链接、邮箱、证件号、电话、长号码、显式隐私字段），并把已选联系人的昵称替换为「对方」。脱敏认不出所有隐私，请自行避免粘贴不愿发送的内容。
- AI 回复下方会标注本次参考了几条档案、是否发生脱敏，便于事后核对。
- 对话只存在浏览器标签页的内存里，刷新即消失；服务端不保存、不写入档案、不写入数据库。切换对话与「新对话」同样只在本地内存中发生。
- 如果出现自伤、被威胁等风险信号，系统提示要求 AI 先表达关心并建议寻求现实中的专业帮助，而不是继续做情感分析。AI 仍可能出错，紧急情况请直接联系可信任的人或当地援助渠道。

接口：`GET /api/fisherman/status`、`POST /api/fisherman/context`（预览背景文字）、`POST /api/fisherman/chat`（SSE 流式回复）。

## 使用说明与心理学依据两页

**使用说明**（导航「使用说明」）回答「这个项目能做什么」：一分钟上手、七个页面各管什么、分数怎么算、五维各看什么、判定区间、四种类型的含义、什么留在本地什么会发出去、输入格式与上限，以及八条常见问题。页面里的阈值、权重、指标说明全部读自 `GET /api/guide`——它和判定逻辑共用 `analyzer.METRIC_WEIGHTS` 与 `report.LEVEL_THRESHOLDS`，所以文档不会和代码说两套话。`backend/tests/test_guide.py` 就是用来锁住这一点的：任何一边改了另一边的数字就会失败。

**心理学依据**（导航「心理学依据」）整理了关系心理学里若干经典理论与效应，按六组编排：亲密关系的结构、依恋与内在工作模型、互动与冲突、承诺与投入、吸引与记忆、以及「流行但实证支持有限」的一组（把证据薄弱的东西单独放，而不是混在结论里）。每条都写明提出者、年份、可核查的出处链接、关键实证发现、证据强度上的注意点，并指出它对应本项目里的哪个指标；条目末尾的「去和钓翁聊聊」会把一个相关问题直接填进「找钓翁聊聊」页的输入框。内容全部在 `frontend/js/theory.js` 里，方便自行增补。

两页都不需要联网（除了跳去找钓翁聊聊），页面目录由各板块标题自动生成，加了板块就会自动出现在目录里。

## 输入与限制

- 支持粘贴文本，每行 `发言者：内容`；也支持 `.xls` 和 `.xlsx`。
- 最稳妥的 Excel 格式为两列：`发言者`、`内容`。首行表头可有可无。其他布局复用原微信解析器，解析后仍须核对发言者。
- 仅支持双人聊天；不会自动识别群聊中的目标，也不会自动合并同名联系人。
- 单文件最多 5 MB；xlsx 解压后最多 25 MB、300 个内部文件。
- 单次最多 1000 行 / 1000 条消息、12 万字；云端模式最多 4 万字。
- 每位联系人最多 200 次更新、500 条信息，每条最多 10 条不同依据。
- 当前本地提取针对明确的第一人称日常喜好，覆盖范围故意较窄。复杂表达、生日、关键事件与完整人格报告未实现。
- AI 观察属于待核实推测。程序检查结构、证据消息是否来自对方，并过滤部分敏感内容；这些检查不能证明 AI 的推断真实。

## 隐私边界

档案保存在 `data/private/`，也可用 `JOKER_PROFILE_DIR` 指定单独目录。`profiles.sqlite3` 保存加密档案，`profile.key` 保存本机密钥，两者均已加入忽略规则。迁移或备份需同时保留这两个文件；丢失密钥无法解密，程序不会静默生成新密钥覆盖旧档案。

完整聊天仅用于当次请求处理与页面预览，不进入档案数据库。原首页分析结果接口不返回完整聊天消息列表，保留仓库已有的隐私保护行为。Excel 上传框架可能使用短期临时文件，处理后关闭。档案保存脱敏后的少量引用、导入时间和更新记录。导出的 JSON 是明文文件，需自行保管。

本机加密降低了单独数据库文件泄漏的风险，但密钥和数据库在同一台机器，不能防御获得本机账号权限的访问者。电话号码、邮箱、长号码等自动脱敏不等于完整匿名化；姓名、地点、上下文仍可能暴露身份。只有明确勾选云端选项才向已配置服务发送当前脱敏片段，旧档案不发送；删除本机联系人不能删除第三方服务日志或已导出的文件。

服务默认仅监听 127.0.0.1，限制 Host 和跨站写请求，API 响应禁止缓存。整站使用本地脚本与样式（不再引用任何 CDN），`/` 与 `/profiles` 都设置了严格 CSP：`default-src 'self'; script-src 'self'`。当前没有多用户登录、账号隔离或生产环境密钥管理，不能直接上线给多人使用。

## 更新规则

数据结构为 `联系人 → 档案条目 → 脱敏依据`，另保存更新批次。没有把旧报告交给 AI 反复全文重写。

- 同一脱敏片段按联系人去重；改名不会自动换联系人，用户负责正确映射。用户明确勾选长文时，允许重新生成本次报告，档案依然去重。
- 同主题、同倾向的本地条目合并；相同句子的依据不重复计数。
- 喜好正反冲突并存，不把导入顺序当作事件时间。当前时间字段均为导入时间，不是聊天发生时间。
- 人工修正保留原始依据和修正标记；之后自动提取只补依据，不覆盖人工文本。
- 删除条目后保留不可读的去重标识，避免同主题同倾向被自动重新写入。删除联系人会一并移除该标识。
- AI 失败时保存本地结果，并区分网络权限、连接、超时、认证、余额、模型或接口不存在、限流、服务异常及返回格式错误。不会显示服务商原始错误正文，避免泄漏密钥或聊天。
- 失败片段可重新上传／粘贴，重新勾选本机保存和云端 AI 后重试：复用原批次，不重复增加聊天更新数量，不覆盖人工修正。已成功完成 AI 的片段仍然去重。
- DeepSeek 官方服务的 V4 模型默认开启思考模式，本实验的短 JSON 摘录明确关闭该模式，避免只生成思考内容或占满有限输出预算。其他服务不附加此参数。参考：[DeepSeek 思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)。
- 相同语义的不同表达（如“徒步 / 爬山”）尚不会智能合并。系统也不把重复出现次数换算成性格置信度。

## 代码与验证

- `backend/app/services/profiles.py`：提取、脱敏、加密持久化、合并、冲突及修正。
- `backend/app/services/unified.py`：`run_unified()` —— 两个模式融合后的唯一实现。
- `backend/app/api/routes/profiles.py`：档案路由：上传解析、脱敏预览、联系人管理与修正接口，含保留的旧入口 `/contacts/{id}/analyze`。
- `backend/app/main.py`：只做应用装配与启动（`create_app()`／`app`），HTTP 路由集中在 `backend/app/api/routes/`；`/` 与 `/profiles` 指向同一个单页工作台；示例与上传接口可携带 `contact_id` 走融合流程；`GET /api/config` 只读地汇报统一配置状态（不回传密钥），`POST /api/config/reload` 用于重载 `.env`。
- `backend/app/schemas/`：请求与响应模型（`base.py` 的 `StrictModel`，以及 `profiles.py`、`fisherman.py`、`system.py`）；各项上限常量集中在 `backend/app/core/config.py`。
- `frontend/index.html`、`css/ink.css`：水墨单页工作台（首页 / 谈心分析 / 分析结果 / 找钓翁聊聊 / 人物档案 / 心理学依据 / 使用说明 / 设置）。
- `frontend/img/`：首页画卷 `siyuan-lake.jpg` 与整站远景水色 `siyuan-lake-soft.jpg`（由 `assets/pictures/交大思源湖.png` 导出，原图不入库）。
- `frontend/js/pond.js`：水墨湖面画布（撒食、鱼群转向与吃食、墨雾遮挡；首页不显示鱼）。
- `frontend/js/ink.js`：融合提交、墨线图表（手绘 SVG 雷达 + 墨线比对）、人物档案渲染、导出图片。
