## 1. 做好了哪些功能

| 功能 | 这次的行为 |

这次还没有生成“相处方法卡”，也没有做按话题给后续 AI 挑选档案。新增 v2 信息暂时不进入问钓翁背景；旧版档案维持原有使用方式。没有重写另一位同学负责的评分、每次聊天提示和统一分析流程。

主入口请使用“人物档案 → 单独更新档案”。原“谈心分析”仍保留旧版的自动喜好摘录流程，因此两个入口的提炼能力目前不同，后续再统一。

## 2. 压缩包是什么

这是**更新包**，需要安装到完整的 JokerDetector 仓库中，不是单独双击运行的软件。它不包含 API Key、私人数据库、真实聊天、图片识别模型、音乐或现有背景图片。

解压后有：

- `files/`：需要加入或替换的代码、测试、这份说明和虚构聊天样例。
- `install_update.py`：安装前检查文件版本、自动备份源码、安装和回退。
- `manifest.json`：文件清单与校验值。
- `changes.patch`：相对于上述 GitHub 基准的差异，供团队查看，正常安装不需要使用它。
- `README.md`：简短入口说明。

更新包兼容前面已经做过的浏览器语音朗读模块，因此带上 `speech.js` 和对应已有样式。朗读测试仍通过；这次没有增加付费 TTS 服务。

## 3. 小白安装步骤（Windows）

### 3.1 先拿到完整项目

已经有完整项目可以跳过此步。没有的话，进入 GitHub 仓库，点 **Code → Download ZIP**，解压得到项目目录，例如 `D:\Projects\JokerDetector`。目录内应同时有 `backend`、`frontend`、`docs` 等文件夹。

这次不要直接覆盖队友的新修改。安装脚本只接受已检查的原版本或前面朗读更新的已知版本；不一致会停下，不会写任何文件。你可以另解压一份上述基准版本到新的目录试用，再由团队合并修改。

### 3.2 停服务和备份

先在原运行终端按 `Ctrl+C` 停止服务。把项目目录复制一份作为备份。尤其需要同时备份 `data/private/profiles.sqlite3` 和 `data/private/profile.key`；只有数据库而没有原密钥，就无法解密。若你设置了 `JOKER_PROFILE_DIR`，备份的是那个目录。

安装脚本会额外备份所替换的源码，但不会代替你的私人数据备份。复制整个项目时，备份文件也应留在本机。

### 3.3 检查并安装更新

把更新包解压到例如 `D:\Downloads\JokerDetector-profile-phase1`。打开 PowerShell，进入更新包目录。以下路径只是例子，请换成自己的实际路径：

```powershell
cd D:\Downloads\JokerDetector-profile-phase1
py install_update.py "D:\Projects\JokerDetector" --check
```

看到 `Checks passed` 表示检查通过。这条命令不会修改项目。接着执行：

```powershell
py install_update.py "D:\Projects\JokerDetector"
```

看到 `Installed. Backup: ...` 表示安装完成。保存这个备份名。如果 `py` 不存在而 `python` 可以运行，把命令中的 `py` 改成 `python`。安装脚本要求 Python 3.10 或以上。

如果显示 `Your versions differ`，说明列出的文件和我检查的版本不同。不要强行覆盖。你可以先在新的原版目录安装，或把 `changes.patch` 和 `files/` 交给团队比较并合并。未通过检查时，项目没有被修改。

### 3.4 安装依赖并启动

已能启动项目的环境可以继续使用。第一次运行建议创建虚拟环境：

```powershell
cd D:\Projects\JokerDetector
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
```

先用独立测试档案目录，避免动你原来的档案：

```powershell
$env:JOKER_PROFILE_DIR = "$pwd\data\private-phase1-test"
cd backend
..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

打开浏览器访问 `http://127.0.0.1:8000`，点击“人物档案”。不用双击 `frontend/index.html`。没有 Key 也能测试新建、手工记录、本地提炼、预览和合并。

**本地模式是少量规则摘录，不是完整大模型理解。**它能识别样例中的慢热、明确分工、群内个人玩笑、文字/语音要求，以及面试和考试事件；其他说法可能没有结果。需要更完整的语义理解时，再启用云端 AI。

测试目录不要提交 GitHub。后续若提交源码，忽略 `.dossier-backups/`、`data/private-phase1-test/` 以及其他自定义档案目录。

## 4. 日常怎样使用

### 4.1 建档、标签和人工信息

1. 在人物档案左侧填写称呼，点“新建并打开”。同名可以再建一份，系统不自动合并。
2. 填写关系标签，以中文或英文逗号分隔；最多 10 个，每个最多 20 字。
3. 写一句关系背景，点“保存标签与背景”。背景是用户备注，不是模型对关系的判断。
4. 展开“手动补充 / 修正信息”，选择类别、填写主题和内容，必要时填写场景。
5. 重要事情可以填写完整事件日期与状态；其他分类不要填写事件日期。
6. 点“新增手动信息”。已有条目点“人工修正”会把内容带回这个表单。

人工补充会显示“受保护”。即使后来上传对方同主题的话，程序也只追加依据。人工修正后，过去内容保留在版本记录中。

### 4.2 导入聊天

1. 展开“单独更新档案”。每行使用 `发言者：内容`，例如 `我：周末有安排吗？`、`小林：我10月12号有面试。`。续行可以接在上一条消息后；两人名称必须和文本一致。
2. 或选择 Excel：使用“发言者、内容”两列即可；原微信布局也沿用现有解析器。
3. 或选择聊天截图：复用项目原有本机 OCR，按选择顺序拼接多张图。OCR 依赖未安装会提示不可用，可先用粘贴文本测试。配置方法仍看原仓库的 OCR 说明，这次没有重写识别算法。
4. 文件解析后内容进入文本框。先改识别错误，确认“我的发言者名称”和“对方的发言者名称”。这次基础页面采用可编辑文本校对，没有另做气泡式校对表。
5. 填“聊天发生日期”，只填写确认过的真实聊天日期；不知道就留空。多天聊天请拆开处理，否则无法正确判断先后顺序。
6. 选填“聊天场景”。同一类交流或同一件事尽量保持一致。不同场次的面试应说明场次、公司或其他区别，避免让模型误认成同一件事。
7. 可以先点“查看脱敏聊天”，检查手机、邮箱等有没有被遮盖。基础脱敏不能覆盖所有隐私，姓名之外的细节仍需你自行检查。
8. 点“提炼并预览更新”。此时旧档案没有变化。
9. 查看每条的更新类型、已有内容、原文依据；默认勾选全部，可以取消不需要的。
10. 勾选保存确认，点“保存勾选的更新”。条目会出现在下面对应分类中，展开即可查看依据和旧版本。

预览期间改聊天、日期、场景或云端选项，预览会自动清空。保存后或其他操作改变了档案版本，也必须重新提炼。30 分钟未保存的预览会失效。

如果没有值得记录的内容，不保存空批次，也不把栏目凑满。不勾选某个候选不会永久拒绝它，再次导入仍有机会选择；只有删除已保存条目才会触发自动屏蔽。

### 4.3 DeepSeek / 云端提炼

沿用项目服务端统一配置，在项目根目录 `.env` 中配置自己的真实信息：

```dotenv
DEEPSEEK_API_KEY=你的真实密钥
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=你的账户可用且支持聊天与JSON输出的模型ID
```

模型 ID 以服务商和你账号实际可用配置为准，不要直接把第三行中文复制成模型名。已有可用配置无需再改。密钥只放服务端，不能写进前端或提交仓库。改完重启服务，或使用原“设置”里的重新加载与测试连接。

档案导入中勾选“使用云端 AI”和云端发送确认，再点提炼。一次成功提炼通常是一次模型请求，使用同一个 API Key，按服务商规则计费；保存本身不调用模型。完整重复且已全部保存的片段会在调用前被拦截。

云端发送内容包括：本次脱敏聊天、日期与场景、最多 80 条已有的**非人工**有效信息摘要，用于匹配同义主题。不会发送完整历史聊天、人工备注、标签或人工受保护条目。旧摘要不算新的依据。云端失败时不修改旧档案，不会静默写入一个降级结果；可重新提炼，或取消云端选项试本地模式。

我没有使用你的真实 Key 做在线模型测试。当前验证覆盖模拟模型返回、同义匹配、原文校验和失败处理；真实模型提炼质量需要你用虚构记录在自己的服务上复查。

## 5. 按这组样例验收

样例全部虚构，位于 `docs/dossier-samples/`。建档“小林”，标签填“同学、室友、小组成员”。粘贴每个文件内容，自己名称填“我”，对方填“小林”；场景先都留空，以便检查同一主题合并。

| 顺序 | 文件与聊天日期 | 预期结果 |
| --- | --- | --- |
| 1 | `01-first.txt`，2026-10-01 | 新增慢热（刚认识时）、分工要明确、群内个人玩笑边界、面试；共 4 条，面试日期 2026-10-12 |
| 2 | `02-more.txt`，2026-10-03 | 分工追加依据；群聊边界细化；条目仍 4 条，不产生“讨厌所有群聊” |
| 3 | `03-change.txt`，2026-10-05 | 新增有条件的语音/文字要求；面试变为 2026-10-15，12 日保留为旧版本；共 5 条 |
| 4 | `04-older.txt`，2026-09-29 | 仅追加历史依据，当前面试仍为 15 日 |
| 5 | 再次上传文件 01，日期仍为 2026-10-01 | 提示完整重复；条目与依据数不增加 |
| 6 | 人工修正慢热条目：熟悉后很健谈，只是刚认识慢热 | 显示人工保护；后续同主题导入不会覆盖这句话 |
| 7 | 新建另一个同名“小林” | 标签、条目独立，不把原档案串过去 |

另外检查：

- 不填聊天日期上传“面试改到15号”，原记录应保留并提示需要确认，不能拿上传时间当作先后依据。
- 已保存一段聊天后，粘贴原内容加一条新面试/考试消息；相同日期与场景下，连续重叠不再增加旧依据，只处理新信息。
- 修改完档案之后保存此前的预览，服务器应拒绝并要求重新生成。
- 删除一条，再上传相同主题或相同旧原话，不会自动恢复；如果你主动想恢复，可以手动新增。
- 点“导出为 JSON”检查字段。导出是明文，包含短原文依据，需要自己保管。

边界说明：本地去重不做跨日期的语义判断；一条相同的“谢谢”不代表同一个事件。模型同义合并依赖正确的主题与场景匹配，遇到两场同名事件或错误归属仍可能误判。因此预览和人工修正是当前阶段的必要操作。

## 6. 给开发者的代码导航

| 文件 | 用途 |
| --- | --- |
| `backend/app/schemas/dossier.py` | 标签、手动条目、导入、保存请求；长度及枚举约束 |
| `backend/app/services/dossier.py` | v2 迁移、手工信息、规则与模型提炼、原文引用校验、合并预览、时间规则、签名预览与原子保存 |
| `backend/app/services/profiles.py` | 继续负责原有加密存储；迁移入口、删除屏蔽、公开返回字段清理 |
| `backend/app/api/routes/profiles.py` | 新的独立档案接口；旧接口保留 |
| `backend/app/api/routes/fisherman.py` | 只增加范围过滤，防止新阶段条目提前进入云端背景 |
| `frontend/js/dossier.js` | 独立页面控制、文件校对、更新预览和分类展示 |
| `frontend/index.html`、`frontend/css/dossier.css` | 档案表单与手机布局；不改聊天评分布局 |
| `frontend/js/ink.js` | 小幅接入档案编辑器、建档后的刷新与导出日期说明 |
| `backend/tests/test_dossier.py` | 连续上传、迁移、锁、去重、删除、预览、云端等回归测试 |
| `frontend/tests/dossier.e2e.cjs` | 真实浏览器完整流程与手机宽度检查，使用独立测试数据 |

关键接口：

```text
PATCH /api/profiles/contacts/{id}                       标签与背景
POST  /api/profiles/contacts/{id}/facts                 手动新增
PUT   /api/profiles/contacts/{id}/facts/{fact_id}        手动完整修正
POST  /api/profiles/contacts/{id}/imports/redact        脱敏查看
POST  /api/profiles/contacts/{id}/imports/preview       提炼与更新预览（不落库）
POST  /api/profiles/contacts/{id}/imports/commit        保存选择的更新
```

预览返回加密认证的短期 token，内部绑定联系人、档案版本、候选、来源摘要及消息哈希；客户端只能选候选 ID，不能把“修改后的模型输出”直接写库。保存用 SQLite 事务并检查版本。一个预览保存后，再次保存会因版本已改变被拒绝。

`schema_version=2` 保留原来的 `facts` 与 `batches`，新增 `category/context/validity/manual_locked/use_in_ai/observed_on/versions/alternatives/event_date/event_status` 等字段。`at` 表示上传时间，`chat_date` 表示用户确认的聊天日期。重要事件不会因为日期已过就自动宣布完成；页面显示“日期已过，结果未知”。

关系标签和背景属于用户输入，不让模型替用户填写。新条目的 `use_in_ai=false` 是本阶段范围限制，暂时没有开放逐条背景使用开关。未来方法卡、背景筛选可以读取同一套条目与引用 ID，不需要再建一份人物真相数据。

源码回退：先停止服务，再在更新包目录执行下面命令，替换目录与备份名：

```powershell
py install_update.py "D:\Projects\JokerDetector" --restore 20261005-xxxxxx-xxxxxx
```

如果安装后又编辑了被替换的文件，脚本会停止回退，避免覆盖新工作。可以手动比较备份。源码回退不会恢复私人数据；想回到安装前的数据，应在停止服务的情况下恢复你自行备份的**数据库与原密钥整对文件**。隔离测试目录则可以留着继续检查。

这次仍是本机单用户档案实现。后续公开网站前，需要独立完成登录、用户隔离和上传授权；这些不是本更新包已实现的功能。
