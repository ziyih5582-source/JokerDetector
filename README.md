## 本次更新：两个模式融合 + 水墨界面 + 硬件归档

**1. 情感分析与联系人档案合并成一条流程。**
现在只有一个界面、一次提交：粘贴或导入一段聊天，同时得到「情感分析」（算法统计、五维墨线、可选 AI 长文）和「名册变动」（喜好提取、依据、冲突、修正）。原来的 `/profiles` 独立页面已并入同一页，旧链接仍然可用。
后端也只保留一条实现：所有入口都走 `POST /api/analyze/unified`（原来的 `/api/profiles/contacts/{id}/analyze` 保留为兼容外壳，内部调用同一段代码）。不选联系人即「只看水纹，不落一笔」，全程不写档案库。

**2. 前端用水墨风重写。**
入口是一片朦胧的鱼塘：点击纸面任意处投食，鱼会摆尾游过来吃掉。鱼不画清晰轮廓线，靠叠加淡墨与阴影扩散做软边，再用前景墨雾遮住一部分，所以水不透彻、鱼时隐时现。
板块之间不用方框和色块，只有细墨线、朱砂点缀与文字层级区分；五维雷达图与双方比对都改成手绘墨线，不再使用 Chart.js，因此页面可以启用严格 CSP，所有绘制都在本机完成。

**3. 新增「问钓翁」：可以和 AI 聊情感问题。**
点进去先选「这次谈谁」：不谈具体的人就是单纯倾诉；选定名册里的某个人并勾选后，AI 会先读到 TA 的脱敏档案（喜好、沟通观察、冲突条目），再以心理疏导者的身份给出贴着这段关系的建议，而不是泛泛安慰。可以随时「新对话」，历史对话只在浏览器内存里，刷新即消失，不写入名册也不入库。发送前在本机对你说的话做基础脱敏（电话、邮箱、证件号等），并把对方昵称替换成「对方」；档案内容只在明确勾选后才发出，并且可以先用「查看将发送的档案内容」核对——所见即所发。

**4. Arduino 硬件联动全部归档。**
`v5_arduino/` 固件、`v5.py` 里的串口代码、`ARDUINO_PORT` 配置都已移到 `archive/`，没有删除，随时可复原（见 `archive/arduino_integration/README.md`）。桌面版 `v5.py` 不再依赖 `pyserial`。

### Windows 快速启动 Web 版

安装 Python 3.12，并在安装时勾选 **Add python.exe to PATH**。下载并解压项目后，进入含有本 README 的文件夹，在资源管理器地址栏输入 `powershell` 并回车，逐行执行：

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r web/requirements.txt
.venv\Scripts\python -m uvicorn main:app --app-dir web/backend --host 127.0.0.1 --port 8000
```

保持窗口打开，浏览器访问 http://127.0.0.1:8000/ 。以后可双击 `start_profiles.bat` 启动。macOS / Linux 把 `.venv\Scripts\python` 换成 `.venv/bin/python` 即可。新功能要求 Python 3.10+，推荐 3.12。

云端 AI 已由项目统一配置，使用者不需要填写 API Key。把 `.env.example` 复制成 `.env`（或直接使用分发方附带的 `.env`），Key 会在启动时自动读取；在「墨设」页点「验证调用」确认可用，然后在「投食」里勾选云端选项即可。没有 Key 时本地统计与喜好提取照常工作。

完整说明：[联系人档案使用教程与实验限制](README_PROFILES.md)。本实验版适合单人本机运行，不包含多用户账号系统。

## 📖 项目简介

你是不是在感情中付出太多却得不到回应？你是不是那个永远在主动的"小丑"？

**Joker Detector Pro** 是一款专为工程学导论课程设计的聊天记录分析工具。它能够：
- 📊 从微信聊天记录 Excel 文件中提取数据
- 🧮 使用多维度算法量化你的"小丑指数"
- 🤖 结合 AI 大模型进行情感关系深度分析
- 💌 生成个性化情感疏导建议
- 🎮 提供"恋爱冷静期"干预弹窗

> ⚠️ 本项目仅供课程学习和娱乐目的，请勿用于实际情感决策。

## ✨ 核心功能

### 1. 数据解析与统计
| 统计维度 | 说明 |
|---------|------|
| 消息数量 | 统计双方消息总数，计算发送比例 |
| 表情包数量 | 检测 `[emoji]` 格式表情 |
| 图片数量 | 检测 `[图片]` 标记 |
| 连续消息数 | 分析消息连续发送的最大 streak |
| 语音/通话记录 | 检测通话行为并施加惩罚系数 |

### 2. 算法评估系统
采用五维度比率综合评分：

```
r1 = 自己的消息数 / 对方消息数
r2 = 自己的表情包数 / 对方表情包数
r3 = 自己的最大连续消息数 / 对方的最大连续消息数
r4 = 自己的总字数 / 对方总字数
r5 = 自己的图片数 / 对方的图片数

jokernum_alg = (r1 + r2 + r3 + r4 + r5) / 5
```

### 3. AI 双重评估
- **小丑指数 AI**：调用大模型分析对话内容，给出 0-1 的小丑评分
- **最终指数** = 算法评分 × AI 评分

### 4. 情感人格类型 (MBTI 风格)

```
dim1: I/P - 主动发起型 / 被动回应型
dim2: E/R - 表达丰富型 / 含蓄克制型
dim3: D/S - 深度表达型 / 浅层交流型
dim4: T/F - 执着纠缠型 / 随性洒脱型
```

典型组合示例：
- 🃏 **IEDT** → 『深情表演家』
- 🃏 **IRDF** → 『沉默的守望者』
- 🃏 **PESF** → 『气氛组选手』

### 5. 情感疏导 AI
基于聊天记录生成 200-300 字的温柔情感疏导，包含：
1. 情绪安抚与认可
2. 问题分析与指出
3. 2-3 条可执行建议

### 6. 恋爱冷静期弹窗 🆕
当检测到高风险小丑行为时，触发全屏红色警告：
- 要求用户输入"我不是小丑" 5 次
- 每次输入错误都会弹出"错误"提示
- 冷静成功后解除警告

## 🚀 快速开始

### 环境要求
- Python 3.8+
- pip 包管理器

### 安装依赖

桌面版（保留 Tkinter GUI，功能最完整）：
```bash
pip install pandas openpyxl xlrd openai httpx pillow pygame
```

Web 版（推荐，唯一界面入口）：
```bash
pip install -r web/requirements.txt
```

### 使用步骤

#### 1. 准备聊天记录
准备已有的 Excel 聊天记录（.xls 或 .xlsx），或在「投食」里直接粘贴 `发言者：内容` 格式的文本。也可以先点一个内置示例（虚构内容）走完整流程。

#### 2. 配置 API（可选）

Web 版采用**统一配置**，使用者无需填写 Key，按下面的优先顺序读取：

1. **项目根目录的 `.env`**（推荐）：把 `.env.example` 复制为 `.env`，填入 `DEEPSEEK_API_KEY` 等变量即可，程序启动时自动加载。改完 `.env` 后若服务已在运行，到「墨设」页点「重新加载配置」即可生效，不必重启。
2. **进程环境变量**：优先级最高，适合 CI 或临时覆盖；若同名变量已存在，`.env` 不会覆盖它。

> `.env` 已被 `.gitignore` 排除。分发时请手动把配置好的 `.env` 随包提供，或让使用者使用真实环境变量。桌面版 `v5.py` 仍保留 GUI 内的 ⚙️ AI 配置 弹窗，可继续手动填写。
>
> 聊天数据默认在本地处理；只有勾选本次云端 AI 选项，才会发送基础脱敏后的片段。

#### 3. 运行分析（Web 版，推荐）

```bash
cd web/backend
python main.py
```
浏览器访问 `http://127.0.0.1:8000/` ，或者在项目根目录用 README 顶部的 uvicorn 命令启动。

流程：点「投食」→ 粘贴或导入聊天 → 「辨认说话的人」→ 核对「我 / 对方」→（可选）在右侧选一个名册条目，决定是否写入档案 → 「洒入水中」。
一次提交同时得到水纹（情感分析）与名册变动（喜好、依据、冲突）。不选名册条目就是纯分析。

想聊感情问题：点「问钓翁」，选好「这次谈谁」（可以不选人），把想说的写下来发送。这个功能需要先配置云端 AI。

想看鱼：回到「水面」或在任意页面点纸面空白处投食。

#### 4. 查看结果
- 算法得分（0-100）+ 判定与类型印章
- 五维墨线图与双方墨线比对
- 名册变动：新增条目、补充依据、正反冲突
- AI 情感分析长文（若勾选并配置了 API）

## ⚙️ 配置说明

### AI API 配置

**Web 版：统一配置（`.env` 或环境变量）**

把 `.env.example` 复制为项目根目录的 `.env`，填入统一的那把 Key：

```env
DEEPSEEK_API_KEY=sk-xxx                          # 项目统一的 API Key
DEEPSEEK_BASE_URL=https://models.sjtu.edu.cn/api/v1  # API 地址（上海交大模型平台，OpenAI 兼容）
DEEPSEEK_MODEL=deepseek-chat                     # 调用名：DeepSeek V4 Flash → deepseek-chat
```

支持任意 OpenAI 兼容服务，换服务商时只需改 `DEEPSEEK_BASE_URL` 与 `DEEPSEEK_MODEL`，注意调用名必须与该平台一致。

程序启动时会自动加载 `.env`；若同名进程环境变量已存在，则以环境变量为准。改完 `.env` 后在「墨设」页点「重新加载配置」即可生效，无需重启。

> `.env` 已被忽略，不会入库。**不要把真实密钥写进 `.env.example` 或源代码**；`DEEPSEEK_API_KEY` 也不要写成 `os.getenv("X", "sk-真实Key")` 这种带默认值的形式。

**桌面版：GUI 运行时配置**

启动 `v5.py` 后，点击左侧面板的 **⚙️ AI 配置** 按钮，即可在弹窗中填写 API Key / Base URL / 模型名称。

> 💡 未配置 API Key 时，程序将使用纯算法模式，跳过 AI 功能，所有聊天记录仅在本地处理。

## 🔐 提交前检查（安全）

本仓库公开，请勿把下面这些东西提交上来：

- **API Key**：统一配置只从 `.env` 或进程环境变量读取。`.env` 本身已被忽略，但仍要确认它没有被 `git add -f` 强制加进来；也绝不要写进 `analyzer.py` 或用 `os.getenv("X", "sk-真实Key")` 这种带默认值的写法——它看起来像占位符，其实是把密钥提交了。分发打包时若把 `.env` 一起给出，请走私下渠道，不要附在公开压缩包里。
- **真实聊天记录**：`database/test1.xls` 是真实私人对话，已在 `.gitignore` 中排除，只在本地保留。要演示请用仓库里的虚构样例或内置 Demo。
- **联系人档案**：`web/private_data/` 存的是加密档案库与密钥，已排除。备份时两个文件要一起带走。
- **商业音乐与配图**：`music/` 与 `pictures/` 里的内容不入库，克隆后请自备同名文件；缺少时程序照常运行，只是没有配乐与配图。

改完这类内容记得检查一下：

```bash
git diff --cached | grep -nE "sk-[A-Za-z0-9_-]{10,}"   # 只看有没有提交密钥
git status --ignored --short | head                     # 看有没有该忽略却被跟踪的文件
```

更稳妥的做法是装一个 `gitleaks` 或 `detect-secrets` 的 pre-commit 钩子，并打开 GitHub 仓库的 push protection。

> 如果密钥曾经被提交过，**吊销并重新生成**才是真正的止损；删文件、改历史都只是补救。
